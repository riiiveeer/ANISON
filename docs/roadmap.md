# ANISON 产品路线与历史改造记录

## 1. 项目目标

把当前项目从“浏览器里的 LRC 歌词分析工具”，升级成一个适合手机长期使用的日语学习应用，核心目标如下：

- 在手机上学习日语歌
- 结合歌词卡持续学日语
- 将歌曲、歌词、学习记录保存在本地
- 支持后续接入网易云歌单导入
- 逐步演进成可长期维护的移动端学习产品

---

## 2. 当前项目现状

### 2.1 已有能力

- 已支持解析 `.lrc` 歌词并生成时间戳分组
- 已支持将歌词分组映射为歌词卡
- 已支持单卡 AI 讲解
- 已有基础本地缓存能力（`localStorage`）
- 已有基础响应式样式，可在小屏幕显示

### 2.2 当前定位

当前项目更接近：

- 单首歌词分析工具
- 桌面浏览器优先页面
- 一次性学习页面

当前项目还不是：

- 手机优先学习应用
- 可持续积累歌曲和学习记录的本地曲库
- 可批量导入和管理歌曲的学习系统

---

## 3. 与目标之间的主要差距

### 3.1 产品能力差距

缺少完整学习闭环：

- 没有歌曲库
- 没有学习进度记录
- 没有每日学习/复习任务
- 没有收藏、掌握、待复习等状态
- 没有“继续上次学习”入口

### 3.2 移动端能力差距

缺少真正面向手机的应用结构：

- 当前布局仍偏桌面双栏
- 缺少首页、歌曲库页、学习页、复习页、设置页
- 缺少底部导航和触屏优先交互
- 缺少 PWA 安装能力和离线能力

### 3.3 数据层差距

当前存储层不足以支撑长期使用：

- 只有 `localStorage`
- 没有本地数据库
- 没有歌曲、歌单、学习记录的数据模型
- 没有长期缓存和迁移策略

### 3.4 导入能力差距

当前只支持：

- 粘贴 LRC
- 上传单个 `.lrc` 文件

当前已补齐的能力：

- 批量导入
- 歌单导入（文本歌单 / 手动列表过渡方案）
- 歌曲去重
- 歌词来源抽象
- 导入失败重试和错误报告

当前仍待完善的能力：

- 更自然的导入交互（例如弹层/抽屉化）
- 更完整的导入结果详情展示
- 更稳的外部歌词源接入与错误恢复

### 3.5 网易云导入现状

公开单曲链接导入已经完成，歌单批量导入仍待后续评估：

- 已支持公开单曲链接、分享文本和歌曲 ID
- 已通过同源本地网关获取原文、翻译和罗马音
- 已支持预览、缺失轨道提示、来源去重和导入后直接学习
- 已抽象歌词提供器、类型化歌词轨道和标准化入库链路
- 不支持登录、会员权限绕过、歌单、专辑和搜索导入

## 4. 总体改造原则

### 4.1 先做本地学习器，再做歌单导入

建议顺序：

1. 先把项目做成手机上可以每天打开学习的应用
2. 再把歌曲、歌词卡、学习状态稳定保存到本地
3. 最后再接入网易云歌单导入

### 4.2 先做本地导入，再做外部平台导入

优先完成本地单曲和批量导入，避免一开始就被外部平台接口稳定性拖慢节奏。

### 4.3 导入链路必须可插拔

不要把项目强耦合到某个平台接口，建议抽象为：

- `playlist-importer`：解析歌单
- `lyric-provider`：获取歌词或 LRC
- `song-importer`：标准化导入和入库

### 4.4 长期数据要从 `localStorage` 升级到 `IndexedDB`

`localStorage` 适合保存：

- API Key
- 少量设置项
- 少量 AI 缓存索引

以下内容建议进入 `IndexedDB`：

- 歌曲库
- 歌词卡
- 学习记录
- 收藏状态
- 复习任务
- 导入记录

## 8. 网易云歌单导入的推荐实现方式

### 8.1 不建议的方案

- 前端直接抓网易云网页
- 前端直接调不稳定的私有接口
- 把歌词获取逻辑写死在 UI 代码里

原因：

- 容易遇到 CORS
- 接口容易变动
- 可能触发鉴权和风控
- 不利于后续更换歌词来源

### 8.2 推荐方案

#### 方案 A：后端代理解析（正式主方案）

流程：

1. 用户输入网易云歌单链接或 ID
2. 后端解析歌单歌曲列表
3. 后端逐首获取歌词或 LRC
4. 前端接收标准化结果
5. 写入本地数据库

优点：

- 前端更稳定
- 可统一处理失败重试
- 可替换解析源
- 更适合未来扩展多平台

#### 方案 B：文本清单导入（过渡方案）

流程：

1. 用户提供歌单里的“歌名 - 歌手”文本
2. 系统按关键词匹配歌词源
3. 命中后生成 LRC 并入库

优点：

- 不依赖网易云接口
- 能先验证批量导入流程

#### 方案 C：本地批量 LRC 导入（第一阶段必做）

流程：

1. 用户选择多个 `.lrc` 文件
2. 前端解析并标准化
3. 去重后入库
4. 生成导入结果报告

优点：

- 最容易落地
- 能先完成歌曲库与学习闭环
- 能验证数据库结构是否合理

## 11. 风险与应对

### 风险 1：一开始就做网易云导入，施工会被外部接口拖慢

应对：

- 先完成本地导入与本地学习闭环
- 把网易云导入放到可插拔层

### 风险 2：继续使用 `localStorage` 承担主数据存储

应对：

- 尽早切到 `IndexedDB`
- 保留 `localStorage` 只存轻量配置

### 风险 3：继续在 `main.js` 上堆功能

应对：

- 尽早拆出 `app / db / render / store / engine` 层

### 风险 4：移动端体验被桌面布局限制

应对：

- 采用移动优先布局
- 优先做单栏、底部导航、可触达按钮区
